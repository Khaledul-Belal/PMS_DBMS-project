# Baribari — Property Management System

সাবস্ক্রিপশন-ভিত্তিক প্রপার্টি ম্যানেজমেন্ট সিস্টেম। বাংলাদেশের বাড়িওয়ালাদের জন্য বানানো — বিল্ডিং, ফ্লোর, রুম, ভাড়াটিয়া, ভাড়া আদায়, বিদ্যুৎ-পানি-ময়লার বিল, মিস্ত্রির খরচ, কেয়ারটেকারের বেতন আর মাস শেষে কত লাভ হলো — সব এক জায়গায়।

DBMS কোর্স প্রজেক্ট। Frontend: pure HTML + CSS + JavaScript (কোনো ফ্রেমওয়ার্ক নাই)। Backend: PHP (PDO)। Database: MySQL।

## ১. কী কী আছে

তিন ধরনের ব্যবহারকারী, তিনটা আলাদা ড্যাশবোর্ড:

**Admin (তুমি — সিস্টেমের মালিক)**
- কতজন প্রপার্টি ওনার সাবস্ক্রাইব করেছে, কত টাকা আয় হয়েছে, কয়টা বিল্ডিং/ইউনিট/ভাড়াটিয়া সিস্টেমে আছে
- প্রতিটা সাবস্ক্রাইবারের বিস্তারিত দেখা, ব্লক করা, ডিলিট করা (ডিলিট করলে তার সব ডেটা cascade হয়ে মুছে যায়)
- সাবস্ক্রিপশন প্ল্যান আর দাম ঠিক করা

**Property Owner (তোমার ইউজার)**
- সাইন আপ করে প্ল্যান বেছে নেওয়া
- বিল্ডিং যোগ করা — চাইলে "১০ তলা, প্রতি তলায় ৩টা রুম" এক ক্লিকে পুরোটা তৈরি হয়ে যায়
- নিজেই ম্যানেজ করা, অথবা ম্যানেজার নিয়োগ দিয়ে তাকে আলাদা লগইন দেওয়া
- কোন বিল্ডিং কোন ম্যানেজারের দায়িত্বে সেটা ঠিক করা
- সব রিপোর্ট দেখা

**Manager (ওনারের নিয়োগ করা লোক)**
- আলাদা লগইন, কিন্তু ডেটা ওনারেরটাই দেখে
- ভাড়া তোলা, বিল এন্ট্রি, মিস্ত্রি ডাকা, বেতন দেওয়া — সব করতে পারে
- নতুন ম্যানেজার নিয়োগ বা বিল্ডিং ডিলিট করতে পারে না

দুইজনেই যা করতে পারে:
- **Floor plan** — বিল্ডিং তলা অনুযায়ী সাজানো, সবুজ = ভাড়া আছে, হলুদ = খালি, লাল = মেরামত চলছে
- **ভাড়াটিয়া ও চুক্তি** — কে কবে উঠলো, কত অ্যাডভান্স দিলো, কত মাসের চুক্তি, কবে শেষ হবে (৬০ দিনের কম থাকলে সতর্কবার্তা), কেউ চলে গেলে ইউনিট আবার খালি হয়ে যায়
- **ভাড়া আদায়** — এক ক্লিকে পুরো মাসের বিল তৈরি, তারপর কে দিলো/কে আংশিক দিলো/কে বাকি রাখলো
- **খরচ** — কারেন্ট বিল, পানির বিল, ময়লার বিল, লিফট সার্ভিসিং, ওয়্যারিং, প্লাম্বিং — ক্যাটাগরি অনুযায়ী
- **স্টাফ ও বেতন** — কেয়ারটেকার, গার্ড, ক্লিনার; মাসিক বেতন শিট
- **মেইনটেন্যান্স** — কী নষ্ট হলো, কে ঠিক করলো, কত টাকা লাগলো। "Done" মার্ক করলে খরচটা স্বয়ংক্রিয়ভাবে expense-এ চলে যায়
- **মাসিক রিপোর্ট** — প্রতি বিল্ডিং আলাদা করে: কত আয়, কত বাকি, কত খরচ, কত বেতন, নিট লাভ। প্রিন্ট করা যায়

## ২. চালাবে কীভাবে

লাগবে XAMPP (অথবা WAMP/LAMP) — PHP 7.4 বা তার উপরে, MySQL 5.7 বা তার উপরে।

**ধাপ ১ — ফাইল রাখো**
পুরো `pms` ফোল্ডারটা XAMPP-এর `htdocs` এ কপি করো:
```
C:\xampp\htdocs\pms\
```

**ধাপ ২ — Apache আর MySQL চালু করো** (XAMPP Control Panel থেকে Start)

**ধাপ ৩ — ডেটাবেস তৈরি করো**
ব্রাউজারে `http://localhost/phpmyadmin` খোলো → উপরে **Import** ট্যাব → `pms/database/schema.sql` ফাইলটা সিলেক্ট করো → **Go**।

ফাইলটা নিজেই `pms_db` ডেটাবেস বানাবে, ১৬টা টেবিল বানাবে আর ডেমো ডেটা ভরে দেবে (২টা বিল্ডিং, ১২টা ইউনিট, ৫ জন ভাড়াটিয়া, ৩ মাসের ভাড়া-খরচের হিসাব) — যাতে লগইন করেই ফাঁকা স্ক্রিন না দেখো।

> MySQL-এ যদি root পাসওয়ার্ড দেওয়া থাকে, তাহলে `backend/config/db.php` ফাইলে `DB_PASS` এ পাসওয়ার্ডটা বসাও।

**ধাপ ৪ — চালাও**
```
http://localhost/pms/frontend/
```

**ডেমো লগইন**

| কে | ইমেইল | পাসওয়ার্ড |
|---|---|---|
| Property Owner | owner@pms.com | 123456 |
| Manager | manager@pms.com | 123456 |
| Admin | admin@pms.com | admin123 |

প্রথমে হোমপেজ আসবে। উপরে **Sign in** বাটনে ক্লিক করলে লগইন পেজ (`login.html`) — সেখানে তিনটা ট্যাব আছে, ঠিক ট্যাবটা বেছে নিয়ে লগইন করতে হবে। Admin ড্যাশবোর্ড আলাদা পেজ (`admin.html`), ইউজারদেরটা আলাদা (`app.html`)।

## ৪. ER ডায়াগ্রাম

`docs/er-diagram.html` ফাইলটা ব্রাউজারে ডাবল ক্লিক করে খোলো — দুইটা ডায়াগ্রামই দেখবে, উপরে Print বাটন আছে (Print → Save as PDF করলে রিপোর্টে দেওয়ার মতো ফাইল পেয়ে যাবে)।

স্যারকে দেখানোর সময় যা বলবে, সেটা `docs/ER-DIAGRAM.md` তে লেখা আছে — কোন entity কেন weak, কোন relationship কেন M : N, participation কোথায় total, আর স্কিমাটা কীভাবে 3NF মানে। ওই ফাইলটা একবার পড়ে যাওয়া ভালো।

সংক্ষেপে:
- **১৬টা entity**, তার মধ্যে ৪টা weak (FLOOR, UNIT, RENT_PAYMENT, SALARY_PAYMENT)
- **১৬টা relationship**, ডায়মন্ড দিয়ে আঁকা; identifying relationship গুলো ডাবল ডায়মন্ড
- **M : N** দুই জায়গায় — OWNER ↔ SUBSCRIPTION_PLAN এবং TENANT ↔ UNIT; দুইটাই আলাদা টেবিলে নেমেছে (`subscription`, `lease`)
- LEASE কে associative entity হিসেবে আঁকা হয়েছে, কারণ এর নিজের attribute আছে এবং RENT_PAYMENT একে রেফার করে

## ৫. API (রেফারেন্স)

সব রিকোয়েস্ট এই ফরম্যাটে: `backend/api/<file>.php?action=<action>`, বডি JSON, উত্তরও JSON (`{ok: true, ...}` অথবা `{ok: false, error: "..."}`)।

| ফাইল | action |
|---|---|
| auth | `signup`, `login`, `logout`, `me`, `plans` |
| properties | `list`, `get`, `create`, `update`, `delete`, `floor_create`, `floor_delete`, `unit_create`, `unit_update`, `unit_delete`, `vacant_units` |
| tenants | `list`, `create`, `update`, `delete`, `lease_list`, `lease_create`, `lease_end` |
| payments | `list`, `generate`, `pay`, `delete` |
| expenses | `categories`, `list`, `create`, `delete` |
| staff | `list`, `create`, `delete`, `salary_list`, `salary_generate`, `salary_pay` |
| maintenance | `list`, `create`, `update`, `delete` |
| managers | `list`, `create`, `update`, `delete`, `assign` |
| dashboard | `summary`, `trend`, `report` |
| admin | `stats`, `owners`, `owner_detail`, `owner_toggle`, `owner_delete`, `plans`, `plan_save`, `subscriptions` |

নিরাপত্তার জন্য যা করা আছে:
- পাসওয়ার্ড `password_hash()` দিয়ে bcrypt করে রাখা, কখনো প্লেইন টেক্সটে না
- প্রতিটা SQL কোয়েরি **prepared statement** — SQL injection বন্ধ
- প্রতিটা API কল-এ সেশন চেক, আর ডেটা `owner_id` দিয়ে স্কোপ করা — এক ওনার আরেক ওনারের ডেটা কোনোভাবেই দেখতে পারে না
- ম্যানেজার শুধু তার ওনারের ডেটা দেখে, এবং owner-only কাজগুলো (ম্যানেজার নিয়োগ, বিল্ডিং ডিলিট) করতে পারে না
- ফ্রন্টএন্ডে সব ইউজার-ইনপুট এস্কেপ করা হয় (XSS)

## ৬. ভাইভায় দেখানোর একটা রুটিন

১. Admin দিয়ে লগইন → Platform overview → "এইটা আমার সিস্টেম, এরা আমার সাবস্ক্রাইবার"
২. লগ আউট → Owner দিয়ে লগইন → Overview → মাস বদলে দেখাও হিসাব বদলায়
৩. Properties → একটা বিল্ডিং খোলো → floor plan দেখাও (কোন তলায় কয়টা রুম, কোনটা খালি)
৪. Tenants → নতুন ভাড়াটিয়া যোগ করো → Leases → তাকে একটা খালি ইউনিটে বসাও → বিল্ডিং-এ ফিরে দেখাও রুমটা এখন সবুজ
৫. Rent collection → "Create this month's bills" → একজনের পেমেন্ট এন্ট্রি দাও
৬. Maintenance → একটা কাজ Done মার্ক করো খরচসহ → Expenses এ গিয়ে দেখাও খরচটা নিজে থেকে চলে এসেছে
৭. Monthly report → নিট লাভ দেখাও
৮. লগ আউট → Manager দিয়ে লগইন → দেখাও একই ডেটা, কিন্তু Managers মেনুটা নাই
৯. শেষে `docs/er-diagram.html` খুলে ডায়াগ্রাম ব্যাখ্যা করো

## ৭. সমস্যা হলে

| যা দেখছো | কারণ |
|---|---|
| "Could not reach the server" | Apache বন্ধ, অথবা ফোল্ডারটা `htdocs` এ নাই |
| "Database connection failed" | MySQL বন্ধ, অথবা `schema.sql` ইমপোর্ট করা হয়নি, অথবা `db.php` তে পাসওয়ার্ড ভুল |
| "Wrong email or password" | ভুল ট্যাবে লগইন করছো (Owner/Manager/Admin) |
| পেজ খালি, ডেটা আসে না | ব্রাউজারে F12 → Console/Network ট্যাবে দেখো কোন API কল ফেল করছে |
| `file:///` দিয়ে খুললে কিছু কাজ করে না | PHP চালাতে হয় সার্ভার দিয়ে; `http://localhost/pms/frontend/` দিয়েই খুলতে হবে |
